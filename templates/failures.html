Resilience & Fallback Demonstration Panel

This panel demonstrates how the system maintains continuity and safety when telemetry data, communication links, or remote feeds fail. Switch failure states on/off below and watch the warnings appear in the app header, maps, and logs.

Case 1: GPS Feed Failure
System Behavior when Active:
  • Stops receiving real-time coordinates.
  • Freezes bus markers at last known coordinates.
  • Calculates travel time using last known location and static route paths.
  • Displays warning on Map and Dashboard.
GPS unavailable. Using last known location.
Case 2: Network Outage (Store-and-Forward)
System Behavior when Active:
  • App enters offline mode. Updates are not pushed to SQLite.
  • Stores events in client-side / local simulation memory queue.
  • Exits queue when network is restored, syncing all updates safely.
  • Reports synchronization metrics inside UI.
Network unavailable. Using store-and-forward mode.
Simulation Queue: 0 | IndexedDB Queue (busTelemetryDB): 0
Case 3: Traffic Feed Disconnection
System Behavior when Active:
  • Disrupts integration with live traffic speeds feed.
  • Falls back to historical default traffic index (MEDIUM).
  • Estimates travel delays based on historical average values.
  • Displays fallback indicator.
Traffic data unavailable. Using fallback traffic estimate.
Case 4: Speed Sensor Discrepancy
System Behavior when Active:
  • Speed sensors report 0 km/h even while bus is transit status.
  • Sanity checker detects reading discrepancy (status ON_ROUTE, speed 0).
  • Falls back to previous valid speed reading or nominal speed limit (30 km/h).
  • Displays warning to admin logs.
Abnormal sensor reading detected. Using previous valid value.
